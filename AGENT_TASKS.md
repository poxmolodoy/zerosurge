# AGENT_TASKS.md — план исправлений для ZeroSurge

Этот файл адресован кодинг-агенту (Claude Code, Codex и т.п.), который работает в репозитории `poxmolodoy/zerosurge`. Положи его в корень репозитория и дай команду: «Выполни задачи из AGENT_TASKS.md по порядку».

## 0. Контекст и правила работы

**Что за проект.** ZeroSurge — локальный трекер отказа от энергетиков и кофеина. Стек: React 18, TypeScript, Vite 5, Tailwind 3, Electron (Windows portable), тесты на Vitest. Данные хранятся в `localStorage`. Бэкенда нет.

**Откуда взяты замечания.** Ревью делалось по README, SECURITY.md и package.json. Исходники `src/` и `electron/` ревьюер **не читал**. Поэтому для каждой задачи:

1. Сначала **проверь утверждение по коду** (grep, чтение файлов). Если замечание не подтвердилось, пропусти задачу и запиши это в отчёт.
2. Только потом правь.

**Жёсткие ограничения (нарушать нельзя):**

- **Не выдумывай источники.** Ни одной ссылки, DOI, PMID или цитаты без проверки по реальной странице (PubMed, DOI.org, сайт ВОЗ). Если не можешь открыть источник и подтвердить утверждение, смягчи или удали утверждение и внеси его в `docs/CONTENT_REVIEW.md` как «не подтверждено».
- **Не добавляй телеметрию, аналитику, внешние запросы и облачные сервисы.** Главный принцип проекта: всё локально.
- **Не меняй лицензию (MIT).**
- **Не делай рефакторинг ради рефакторинга.** Только то, что нужно для задачи.
- **Не пиши в документацию утверждения, которых не можешь подтвердить** (например «0 уязвимостей», «одобрено»). Формулируй точно и проверяемо.
- Один логический блок работы равен одной ветке и одному PR (или хотя бы одному коммиту) с понятным сообщением на английском в формате Conventional Commits.

**Перед каждым коммитом должны проходить:**

```
npx tsc --noEmit
npm test
npm run build
```

Если что-то упало и починить в рамках задачи нельзя, остановись и опиши проблему в отчёте. Тесты не отключай и не удаляй, чтобы «позеленело».

## Приоритет P0 — сделать в первую очередь

### P0-1. Исправить медицинский контент и добавить источники

**Проблема.** Проект называет себя «доказательным клиническим ассистентом», но ссылок на источники нет, а часть утверждений неточна.

**Шаги:**

1. Найди весь клинический контент: `src/data/**`, тексты в `src/components/*Modal*.tsx`, `CaffeineHarm*.tsx`, `MilestoneDetailModal.tsx`, а также README.
2. Составь таблицу всех утверждений (что утверждается, где лежит в коде, чем подтверждено) в `docs/CONTENT_REVIEW.md`.
3. Проверь и исправь по реальным источникам. Особое внимание этим пунктам:

| Утверждение в проекте | Что проверить и как исправить |
|---|---|
| Пик тяги на 3–4 день | В литературе (Juliano & Griffiths, 2004, *Psychopharmacology* 176:1–29) абстиненция от кофеина начинается через 12–24 ч, пик приходится на 20–51 ч, длительность обычно 2–9 дней. Привести временную шкалу в соответствие и убедиться, что источник открывается и говорит именно это |
| «Через пару месяцев без энергетика человек чувствует тяжёлый провал» / «кофеиновый долг» | Утверждение выглядит неподтверждённым. Если надёжного источника нет, удали или перефразируй (например, что толерантность и чувствительность аденозиновых рецепторов обратимы за период от дней до нескольких недель, и только с источником) |
| «Истощение надпочечников» | Adrenal fatigue не является признанным диагнозом. Удали термин. Если нужно говорить о стрессовой оси, используй осторожную формулировку «активация симпатоадреналовой и HPA-оси» и только при наличии источника |
| «55 г сахара превышает суточный лимит ВОЗ в 2 раза» | Рекомендация ВОЗ 2015: свободных сахаров менее 10% энергии (около 50 г при 2000 ккал), желательно менее 5% (около 25 г). Исправь формулировку (например «около суточного лимита ВОЗ / вдвое выше желательного уровня») и привяжи к источнику |
| «Подъём давления на 10–15 мм рт. ст.» | Проверь по обзорам или метаанализам, учитывая зависимость от толерантности. Укажи диапазон и условия, либо смягчи |
| Механизмы (β1-адренорецепторы, цАМФ, A1/A2A) | Проверь, что формулировки корректны и не выдают гипотезу за доказанный факт |
| Сроки восстановления по системам организма | Для каждого срока найди источник или пометь как «ориентировочно, у разных людей по-разному» |

4. Расширь схему данных: каждый клинический элемент получает поле `sources: { title: string; url: string; year?: number }[]` (минимум один источник). Добавь тест, который падает, если у элемента клинических данных нет источников или URL не начинается с `https://`.
5. В UI добавь блок «Источники» в модальные окна атласа и этапов восстановления. Ссылки открываются через уже существующий механизм (`setWindowOpenHandler` → системный браузер).
6. Замени в README и в интерфейсе формулировку «клинический ассистент» на «информационно-просветительский трекер», если задача не решена полностью. Дисклеймер оставь заметным: у человека с аритмией, гипертонией или тяжёлой зависимостью первым шагом должен быть врач.

**Критерии приёмки:**
- [ ] Нет ни одного клинического утверждения без источника или явной пометки «ориентировочно».
- [ ] `docs/CONTENT_REVIEW.md` содержит таблицу «утверждение → источник → статус (подтверждено / смягчено / удалено)».
- [ ] Тест на наличие источников проходит.
- [ ] В отчёте перечислены все изменённые или удалённые утверждения.

### P0-2. Экспорт и импорт данных

**Проблема.** Всё лежит в `localStorage`. Сброс профиля или переустановка стирают многомесячный прогресс.

**Шаги:**

1. Добавь в Header или в настройки кнопки «Экспорт» и «Импорт».
2. Экспорт скачивает JSON: `{ schemaVersion: 1, exportedAt: ISO-строка, data: {...} }`.
3. Импорт читает файл, **проводит данные через `securityValidator.ts`** (prototype pollution, bounds, даты), показывает превью («будет загружено: N чек-инов, дата старта …») и просит подтверждение перед перезаписью. Невалидный файл даёт понятную ошибку на русском, а текущие данные не меняются.
4. Поддержка миграций: при `schemaVersion` выше известного импорт отклоняется с сообщением.
5. Добавь тесты: корректный round-trip, битый JSON, подмена `__proto__`, значения вне диапазонов, неизвестная версия.

**Критерии приёмки:**
- [ ] Экспорт, затем очистка `localStorage`, затем импорт восстанавливает состояние один в один (тест).
- [ ] Импорт не может перезаписать данные невалидным файлом.
- [ ] Работает и в вебе, и в Electron (в Electron загрузка файла через стандартный `<input type="file">` и скачивание через `<a download>` либо через IPC `dialog`, если иначе не работает).

### P0-3. Убрать внешние запросы и закрыть их политикой CSP

**Проблема.** Рекомендованный в SECURITY.md CSP разрешает `fonts.googleapis.com` и `fonts.gstatic.com`. Если шрифты грузятся с Google, это внешний запрос с IP пользователя, что противоречит обещанию «ноль данных».

**Шаги:**

1. Проверь `index.html`, CSS и `tailwind.config.js` на внешние URL: `grep -rnE "https?://" index.html src public electron`.
2. Если есть Google Fonts, скачай нужные начертания, положи в `src/assets/fonts` (или `public/fonts`) и подключи через `@font-face` с локальными файлами. Проверь лицензию шрифта (OFL/Apache) и добавь файл с атрибуцией при необходимости.
3. Добавь CSP через `<meta http-equiv="Content-Security-Policy">` в `index.html` (и/или через `session.defaultSession.webRequest.onHeadersReceived` в `electron/main.cjs`), например: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'`. Если `'unsafe-inline'` для стилей нужен из-за framer-motion, оставь и запиши причину в комментарии.
4. Добавь тест или скрипт `npm run check:offline`, который собирает проект и проверяет, что в `dist/` нет подстрок `http://` / `https://` кроме заведомо разрешённых (ссылки на источники в данных, `w3.org` в SVG-namespace). Список исключений задокументируй.

**Критерии приёмки:**
- [ ] Приложение работает с отключённой сетью и выглядит так же.
- [ ] В DevTools на вкладке Network при запуске нет ни одного внешнего запроса.
- [ ] CSP применён и приложение не ломается.

### P0-4. CI и воспроизводимый релиз с контрольными суммами

**Проблема.** 97 МБ неподписанный exe без проверяемой связи с исходниками. Нет CI.

**Шаги:**

**Критерии приёмки:**
- [ ] CI зелёный на `main`.
- [ ] Релиз по тегу автоматически собирает exe и публикует его вместе с `SHA256SUMS.txt`.

### P1-2. Hardening Electron

В `electron/main.cjs`:

- `sandbox: true` в `webPreferences` (проверь, что `preload.cjs` продолжает работать).
- `webContents.on('will-navigate', ...)` блокирует любую навигацию, кроме приложения.
- `session.defaultSession.setPermissionRequestHandler((_, __, cb) => cb(false))` запрещает все разрешения (камера, микрофон, геолокация и т.д.).
- `webSecurity` оставь включённым, `allowRunningInsecureContent: false`.
- Убедись, что `devTools` недоступны в production-сборке.
- Добавь тест или проверочный скрипт, который читает `main.cjs` и проверяет наличие критичных настроек (простая статическая проверка).

### P1-3. Режим «данные рядом с exe» для portable

В electron-builder для portable доступна переменная `PORTABLE_EXECUTABLE_DIR`. Если она задана, при старте вызывай `app.setPath('userData', path.join(process.env.PORTABLE_EXECUTABLE_DIR, 'ZeroSurgeData'))` до `app.whenReady()`. Тогда данные действительно переезжают с флешкой. Сделай это поведением по умолчанию для portable-сборки либо включаемым флагом и опиши в README. Проверь, что `localStorage` сохраняется между запусками.

### P1-4. Режим постепенного снижения и учёт потребления

Сейчас приложение умеет только «отказ в ноль». Добавь:

- Журнал потребления: дата и время, тип (энергетик / кофе / чай / другое), объём, мг кофеина (с редактируемыми пресетами, а не «зашитыми» значениями без источника).
- Режим taper: пользователь выбирает стартовую суточную дозу и срок (например, 2–4 недели), приложение показывает ежедневный лимит и прогресс. Формулы вынеси в `src/utils/` и покрой тестами.
- Всё остаётся локальным, данные входят в экспорт/импорт (P0-2) с повышением `schemaVersion`.
- Для порогов (например, безопасная суточная доза) указывай источники, как в P0-1. Не выдавай свои числа за рекомендации врачей.

### P1-5. PWA и мобильная версия

- Подключи `vite-plugin-pwa`: manifest, иконки, service worker с офлайн-кэшем только собственных ресурсов (никаких внешних запросов).
- Адаптив под телефон: проверь все модальные окна на ширине 360 px.
- GitHub Pages workflow для веб-версии (`base` в `vite.config.ts` должен соответствовать имени репозитория).
- После публикации добавь ссылку на веб-версию в README и в описание репозитория.

### P1-6. Гигиена репозитория

- `CHANGELOG.md` (формат Keep a Changelog), `CONTRIBUTING.md`, шаблоны issue и PR.
- ESLint + Prettier + `.editorconfig`, скрипты `lint` и `format`, запуск в CI.
- Исправь `package.json`: автор, `repository`, `homepage`, `bugs`, `license: "MIT"`, поле `description` без слова «PRO».

- **Зависимости dev:** обнови пакеты с замечаниями `npm audit` (`braces`, `tinypool`, `esbuild`), если это возможно без поломки сборки.
